# Augur Git 使用文档

> 审查改动，决定哪些成为历史。

Augur Git 是一款面向本地 AI 辅助开发、以代码审查为先的跨平台桌面 Git 客户端。它把本地仓库的变更转化为清晰、可导航的差异，让开发者在下一次提交或推送之前理解、选择并确认哪些内容应该进入项目历史。

Augur Git 专门负责“审查”这一层：终端负责运行项目，编辑器负责精确修改，编码代理负责生成较大范围的变更，而 Augur Git 位于这些变更和下一次提交之间。它不试图取代终端、编辑器或编码代理，也不是代码质量自动评判器或托管 Pull Request 平台。

## 产品定义

Augur Git 的核心问题是帮助开发者回答：

- 改动了什么？
- 这些改动为什么重要？
- 哪些部分应该保留、修改或丢弃？
- 仓库是否已经准备好进行下一次提交或推送？

这里的几个概念是产品体验的基础：

- **以审查为先（review-first）**：差异、变更文件和仓库上下文是界面的中心，而不是附带功能。
- **本地优先（local-first）**：通过系统 `git` 检查本地仓库，不要求账号，也不依赖托管服务才能审查变更。
- **人在回路中（human in the loop）**：会改变仓库数据的操作都需要明确的用户动作，并显示操作结果或错误。
- **协作而不替代**：Augur Git 与终端、编辑器和编码代理并列协作，把最终判断留给开发者。

## 推荐工作流

```text
编码代理或编辑器
          |
          v
       工作区变更
          |
          v
      Augur Git 审查
          |
          +----> 将问题交回编辑器或编码代理
          |
          v
       暂存、提交、推送
```

## 功能概览

- **仓库状态**：查看当前分支、领先 / 落后远程的提交数，以及已暂存和未暂存的文件变化。
- **工作区审查**：查看已暂存、未暂存和未跟踪文件的逐文件差异，按文件或分组暂存 / 取消暂存变更，也可以在确认后丢弃变更。
- **原生差异体验**：在全部文件或单个文件之间导航，使用行内 / 并排布局、语法感知渲染和字符级变更高亮。
- **提交历史**：按分支线路查看提交历史，并检查提交的哈希、信息、作者、相对时间和文件差异。
- **分支与引用**：浏览本地分支、远程、远程分支、标签和贮藏，并从侧栏执行常见引用操作。
- **远程操作**：从工具栏执行 Fetch、Pull（Merge 或 Rebase）、Push 和 Force Push。
- **版本比较**：以 Base → Target 的方向比较两个分支、远程分支、标签或提交 SHA，不需要切换工作区。
- **多仓库标签页**：同时打开多个仓库，最近打开的仓库会被记住。
- **主题与语言**：支持 GitHub Dark、Catppuccin 系列主题，以及英文和简体中文界面。

Augur Git 不内置 Git 实现，运行仓库操作时需要系统中已经安装 Git，并且 `git` 命令可以在 `PATH` 中找到。

## 下载与运行

Nightly 版本可以从 [Augur Git GitHub Releases](https://github.com/algosoft-lab/augur-git/releases/tag/nightly) 下载。根据操作系统选择对应的构建产物；Nightly 发布页中的文件名可能随版本调整。

首次运行前，请确认：

1. 系统已经安装 Git。
2. 在终端中执行 `git --version` 能够正常返回版本信息。
3. 使用 Augur Git 打开一个本地 Git 仓库目录。

## 打开仓库

启动应用后，在欢迎页选择 **打开**，然后选择一个 Git 仓库文件夹。也可以把仓库文件夹拖到欢迎页中。

打开仓库后，顶部标签页显示当前仓库；通过 **新建标签页** 可以继续打开其他仓库。最近打开的仓库会显示在欢迎页的最近仓库列表中。

## 查看和提交工作区变更

侧栏的 **Staged** 和 **Changes** 区域分别表示已暂存和工作区中的变更：

1. 在 **Changes** 中选择文件，查看未暂存差异。
2. 使用文件或分组的 **Stage Changes** 将变更加入暂存区。
3. 在 **Staged** 中检查即将提交的文件和差异。
4. 在提交面板输入提交信息，点击 **Commit** 创建提交。

已暂存的文件可以使用 **Unstage Changes** 移回工作区。**Discard Changes** 会先显示确认对话框；对未跟踪文件的丢弃操作会永久删除明确确认的文件，无法撤销。

## 提交历史与差异

提交图展示当前仓库的提交历史。选择提交后，可以查看该提交的文件清单、增删统计和逐文件差异；悬停或打开提交信息可以检查完整提交消息、作者和共同作者。

底部差异面板支持在全部变更文件和单个文件之间切换。对于合并提交，差异默认相对于第一个父提交展示。

## 分支、远程与标签

侧栏会列出本地分支、远程分支、标签和贮藏。选择分支可以查看其信息，并通过上下文菜单执行切换、重命名、删除或合并等操作。

工具栏中的常用远程操作包括：

- **Fetch**：获取远程更新，不修改当前工作区。
- **Pull（Merge）**：获取更新并使用合并方式整合到当前分支。
- **Pull（Rebase）**：获取更新并将当前分支变基到远程更新之上。
- **Push**：推送当前分支到其上游远程分支。
- **Push（Force）**：强制推送。它可能覆盖远程历史，请只在确认远程分支状态后使用。

分支新建、合并、变基、贮藏和标签操作会通过对话框确认目标。变基会改写提交历史，不建议对已经共享的分支执行。

## 比较两个版本

点击工具栏中的 **Compare** 打开只读的版本比较窗口。分别选择 **Base** 和 **Target**，然后点击 **Compare**：

- 可以选择本地分支、远程跟踪分支、标签和当前历史中的提交。
- 也可以打开 **Manual input**，输入分支、标签或 7–64 位十六进制提交 SHA。
- 比较方向是 `Base commit → Target commit`，交换两端会反转增删方向。
- 比较过程不会 checkout、fetch，也不会修改 `HEAD`、暂存区或工作区。
- 选择全部变更文件或单个文件即可查看对应差异。

## 设置与主题

打开 **Settings** 可以调整：

- 界面语言：English 或简体中文。
- 主题：GitHub Dark 与 Catppuccin Latte、Frappé、Macchiato、Mocha。
- 差异布局：根据窗口宽度选择行内或并排显示。
- 提交历史加载数量、界面字体和等宽字体。
- 窗口重新获得焦点时是否自动刷新。

设置会持久化保存，主题和语言可以在运行时切换。

## 配置、数据与日志

应用配置和最近仓库列表保存在平台标准配置目录下的 `augur-git/config.json`。窗口几何和全局面板布局保存在同目录的 `augur-git/ui-state.json`。

调试构建会在工作目录追加写入 `debug.log`；发布构建默认不写入日志文件。需要更详细日志时，可以通过 `RUST_LOG` 调整日志级别。

## 支持的平台

Augur Git 当前支持：

- Windows
- macOS
- Linux（X11 和 Wayland）

## 从源码构建

从 [Augur Git 仓库](https://github.com/algosoft-lab/augur-git) 获取源码后，需要准备稳定版 Rust 工具链和系统 Git：

```bash
cargo run --release
```

构建本地发布包和平台安装包的说明见仓库中的 `packaging/README.md`。

## 常见问题

### 为什么 Augur Git 无法打开或刷新仓库？

请先在终端运行 `git --version`，确认 Git 已安装并位于 `PATH` 中。然后确认所选目录是 Git 仓库，且当前用户对该目录有读写权限。

### 丢弃变更可以恢复吗？

不能。丢弃已跟踪文件的修改会清除工作区内容；确认删除未跟踪文件后，文件也会被永久删除。执行前请确认文件列表和操作范围。

### 比较版本会切换分支吗？

不会。版本比较只读取仓库已有对象和引用，比较过程中不会 checkout 或隐式 fetch。
